# 부산대 도서관 빈자리 대기 예약 봇

부산대 도서관 앱에서 자리가 없을 때 일정 간격으로 조회하다가, 빈자리가 나면 예약하거나 알림을 보냅니다.
아이폰이나 아이패드에서 버튼 하나로 실행하고, 실제 실행은 GitHub Actions(클라우드)에서 합니다. 그래서 휴대폰 화면을 꺼도 계속 돌아갑니다.

> ⚠️ **현재 상태:** 부산대 도서관 앱의 API(서버 주소, 요청 형식)가 아직 확인되지 않아서 `seatbot/client.py`의 `PnuLibraryClient`가 비어 있습니다.
> 아래 **1단계**에서 앱 트래픽을 캡처해야 실제로 동작합니다.

## 동작 방식

1. 학번과 비밀번호로 로그인합니다. 이미 이용 중인 좌석이 있으면 바로 종료합니다.
2. `INTERVAL_SEC`(기본 3초, 최소 2초)에 0~50% 무작위 시간을 더한 간격으로 열람실 좌석을 조회합니다. 오류가 나면 최대 60초까지 점점 더 오래 쉽니다.
3. 빈자리가 나면 선호 좌석 순서대로 **한 자리만** 예약하고, 아이폰으로 푸시 알림을 보냅니다.
4. 정해진 시간(`DURATION_MIN`) 안에 자리가 나지 않거나 오류가 5번 연속 나면 종료하고 알림을 보냅니다.

`notify_only`를 켜면 예약은 하지 않고 "빈자리 발견" 알림만 보냅니다.

## 1단계: 앱 API 캡처하기 (최초 1회)

1. App Store에서 **Proxyman** 앱을 설치하고, 앱 안내에 따라 VPN 프로필과 인증서를 설치한 뒤 신뢰 설정을 합니다.
2. Proxyman에서 캡처를 켠 상태로 부산대 도서관 앱을 열고 다음을 순서대로 합니다. 동작 사이에는 5초 정도 쉽니다.
   - 로그아웃 후 다시 로그인
   - 메인 화면(열람실별 남은 좌석 수) 새로고침 2~3번
   - 열람실 도면 열기 (2곳 이상)
   - 좌석 예약 (빈자리가 있을 때)
   - 내 예약/이용 현황 보기
   - (가능하면) 반납
3. 각 동작에서 `pusan.ac.kr` 같은 학교 도메인으로 나간 요청의 **URL, 메서드, 헤더, 요청 본문, 응답 본문**을 복사해 주세요.
   **비밀번호, 토큰, 쿠키 값은 `***`로 지우고** 공유해 주세요.

이 정보를 주시면 `PnuLibraryClient`를 완성하겠습니다.
메인 화면의 남은 좌석 수가 요청 한 번으로 모든 열람실 정보를 준다면, 평소에는 그 숫자만 확인하고 고른 열람실에 자리가 났을 때만 도면을 조회하도록 바꿀 예정입니다.
앱이 인증서 고정(certificate pinning)을 쓰면 캡처가 안 될 수 있습니다. 그때는 PC 브라우저용 웹 예약 페이지가 있는지 찾아보는 방법으로 바꿉니다.

## 2단계: GitHub 설정

저장소에서 **Settings → Secrets and variables → Actions**로 들어가 다음 값을 등록합니다.

| 종류 | 이름 | 값 |
|---|---|---|
| Secret | `PNU_ID` | 학번 |
| Secret | `PNU_PW` | 비밀번호 |
| Secret | `NTFY_TOPIC` | 알림 토픽 이름. 남이 추측하기 어려운 긴 문자열로 정합니다 (예: `pnu-seat-x8f2k9q`) |
| Variable | `ROOMS` | 평소에 쓸 열람실, 쉼표로 구분 (실행할 때 바꿀 수 있음) |
| Variable | `INTERVAL_SEC` | 조회 간격(초, 선택, 기본 3, 최소 2) |

**알림 받기:** App Store에서 **ntfy** 앱을 설치하고 위 `NTFY_TOPIC`을 구독합니다.

## 열람실과 좌석 고르기

**열람실 (`rooms`):**
- 쉼표로 여러 개를 고를 수 있습니다 (예: `제1열람실, 노트북열람실`).
- **고른 열람실만** 조회하고 예약합니다. 앞에 적은 열람실일수록 우선합니다.
- 열람실 이름과 시스템 내부 ID의 대응은 `rooms.json`에 적습니다 (1단계 캡처 후 채움). 예:

  ```json
  {"제1열람실": "101", "제2열람실": "102", "노트북열람실": "103"}
  ```

- `rooms.json`이 비어 있는 동안에는 입력한 값을 내부 ID로 그대로 씁니다.

**좌석 (`seats`):** 비워 두면 고른 열람실의 아무 빈자리나 잡습니다. 적으면 적은 순서대로, 적은 자리만 노립니다.

| 적는 법 | 뜻 |
|---|---|
| `A12` | 고른 열람실 어디든 A12번 |
| `제1열람실:A12` | 제1열람실의 A12번만 |
| `제2열람실:*` | 제2열람실의 아무 자리 |

예를 들어 `제1열람실:A12, 제1열람실:A13, 제2열람실:*`로 적으면 다음 순서로 노립니다.
1. 제1열람실 A12
2. 제1열람실 A13
3. 둘 다 없으면 제2열람실 아무 자리

열람실을 여러 개 고르면 한 번 확인할 때 열람실 수만큼 요청이 나갑니다. 적발 위험을 생각해서 꼭 필요한 열람실만 고르세요.

## 3단계: 아이폰에서 실행

**GitHub 앱 사용:** 저장소 → Actions → "좌석 대기 예약" → **Run workflow**를 누르고 대기 시간, 열람실, 선호 좌석, 알림만 받기 여부를 정해 실행합니다.

**중단하기:** 실행 중인 작업에서 Cancel을 누릅니다.

**단축어 앱 사용(선택):** 단축어 앱의 "URL의 콘텐츠 가져오기"로 GitHub API(`POST /repos/{owner}/{repo}/actions/workflows/seatbot.yml/dispatches`)를 호출하면 홈 화면 버튼 하나로 실행할 수 있습니다.

## 로컬 실행 및 테스트

```sh
pip install -r requirements.txt
PNU_ID=... PNU_PW=... ROOMS="제1열람실,제2열람실" SEATS="제1열람실:A12" python -m seatbot
python -m unittest -v   # 네트워크 없이 가짜 클라이언트로 테스트
```

## 주의사항

- **이용 규정:** 도서관 이용 규정에 매크로나 자동 예약 금지 조항이 있는지 먼저 확인하세요. 적발되면 이용 정지 등의 불이익이 있을 수 있으며, 그 책임은 사용자에게 있습니다.
- **공정한 사용:** 본인 좌석 1석만, 사람이 손으로 새로고침하는 속도(약 2초에 1번)를 넘지 않도록 만들었습니다. 최소 간격 2초는 일부러 둔 제한이니 낮추지 마세요.
- **적발 위험:** 사람은 몇 시간 동안 쉬지 않고 새로고침하지 않습니다. 2~3초 간격으로 6시간 돌리면 요청이 약 7천~1만 번 쌓여 서버 로그에서 눈에 띌 수 있습니다. 실제로 자리가 필요한 시간대에만 짧게 돌리세요.
- **해외 IP 차단 가능성:** GitHub Actions 서버는 해외에 있어서 학교 서버가 해외 IP를 막으면 동작하지 않을 수 있습니다. 그런 경우 집 PC에서 실행하거나, 아이패드의 a-Shell 앱에서 실행해야 합니다. a-Shell에서는 앱을 화면에 켜둔 상태여야 계속 실행됩니다.
- **입실 확인:** 자리를 예약한 뒤 정해진 시간 안에 입실 확인을 하지 않으면 자동 반납되거나 불이익이 있을 수 있으니 알림을 받으면 바로 이동하세요.
