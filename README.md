# 부산대 도서관 빈자리 대기 예약 봇

새벽벌도서관 열람실에 자리가 없을 때 일정 간격으로 남은 좌석을 확인하다가, 원하는 열람실에 빈자리가 나면 배정받고 아이폰으로 알림을 보냅니다.
아이폰이나 아이패드에서 버튼을 눌러 실행하고, 실제 실행은 GitHub Actions(클라우드)에서 합니다. 그래서 휴대폰 화면을 꺼도 계속 돌아갑니다.

## 동작 방식

부산대 도서관 앱은 `lib.pusan.ac.kr` 웹 화면을 그대로 띄우는 앱이고, 좌석 기능은 Pyxis 시스템의 `/pyxis-api`로 통신합니다. 2026년 10월 앱 캡처로 확인했고, 자세한 요청 형식은 `seatbot/client.py` 맨 위에 적어 두었습니다.

1. 학번과 비밀번호로 로그인합니다. 이미 배정받은 좌석이 있으면 바로 종료합니다.
2. `INTERVAL_SEC`(기본 3초, 최소 2초)에 0~50% 무작위 시간을 더한 간격으로 **열람실별 남은 좌석 수**를 확인합니다.
   - 앱 메인 화면과 같은 요청이고, 한 번에 모든 열람실 정보를 받습니다. 그래서 열람실을 여러 개 골라도 요청 수가 늘지 않습니다.
3. 고른 열람실 중 남은 좌석이 생긴 곳이 있을 때만 그 열람실 도면을 불러와 원하는 자리를 찾습니다.
4. 찾으면 **한 자리만** 배정받고 알림을 보냅니다. 다른 사람이 먼저 잡으면 다음 후보 자리를 시도합니다.
5. 정해진 시간(`DURATION_MIN`) 안에 자리가 안 나거나 오류가 5번 연속 나면 종료하고 알림을 보냅니다. 오류가 나면 최대 60초까지 점점 더 오래 쉽니다.

> ⏱️ **배정 후 15분 안에 입실 확인을 해야 합니다.** 앱으로 배정받으면 "임시배정" 상태가 되고, 입실 확인은 도서관 **게이트나 키오스크**에서만 됩니다.
> 봇은 입실 확인을 대신하지 않으니, 도서관 근처에 있을 때 실행하세요.

### 실행 모드 (`mode`)

| 모드 | 하는 일 |
|---|---|
| `reserve` | 빈자리가 나면 배정받습니다 (기본) |
| `notify` | 배정받지 않고 "빈자리 발견" 알림만 보냅니다 |
| `check` | 로그인하고 남은 좌석 수만 한 번 확인해 알림으로 보냅니다. **처음 설정한 뒤에는 이 모드로 먼저 시험해 보세요.** |

## 1단계: GitHub 설정

저장소에서 **Settings → Secrets and variables → Actions**로 들어가 다음 값을 등록합니다.

| 종류 | 이름 | 값 |
|---|---|---|
| Secret | `PNU_ID` | 학번 |
| Secret | `PNU_PW` | 비밀번호 |
| Secret | `NTFY_TOPIC` | 알림 토픽 이름. 남이 추측하기 어려운 긴 문자열로 정합니다 (예: `pnu-seat-x8f2k9q`) |
| Variable | `ROOMS` | 평소에 쓸 열람실, 쉼표로 구분 (실행할 때 바꿀 수 있음) |
| Variable | `INTERVAL_SEC` | 조회 간격(초, 선택, 기본 3, 최소 2) |

**알림 받기:** App Store에서 **ntfy** 앱을 설치하고 위 `NTFY_TOPIC`을 구독합니다.

## 열람실과 좌석 고르기

**열람실 (`rooms`):** 아래 이름을 쉼표로 구분해 적습니다 (예: `3열람실-A, 3열람실-D`).
- **고른 열람실만** 노리고, 앞에 적은 열람실일수록 우선합니다.
- 고를 수 있는 이름은 `rooms.json`에 있습니다.

| 층 | 열람실 |
|---|---|
| 1층 | 새벽누리-열람존, 새벽누리-미디어존 |
| 2층 | 새벽별당[24h]-A, 새벽별당[24h]-B, 1열람실 |
| 3층 | 2열람실-A, 2열람실-B, 2열람실-C, 2열람실-D |
| 4층 | 3열람실-A, 3열람실-B, 3열람실-C, 3열람실-D, 노트북열람실-A, 노트북열람실-B, 대학원캐럴실 |

**좌석 (`seats`):** 앱 도면에 보이는 좌석 번호를 적습니다. `50`과 `050`은 같은 자리로 봅니다.
- 비워 두면 고른 열람실의 아무 빈자리나 잡습니다.
- 적으면 적은 순서대로, 적은 자리만 노립니다.

| 적는 법 | 뜻 |
|---|---|
| `50` | 고른 열람실 어디든 50번 |
| `3열람실-A:50` | 3열람실-A의 50번만 |
| `3열람실-D:*` | 3열람실-D의 아무 자리 |

예를 들어 `3열람실-A:50, 3열람실-A:51, 3열람실-D:*`로 적으면 다음 순서로 노립니다.
1. 3열람실-A 50번
2. 3열람실-A 51번
3. 둘 다 없으면 3열람실-D 아무 자리

**열람실 목록이 바뀌었을 때:** 도서관이 열람실을 바꾸면 `check` 모드가 남은 좌석을 `?`로 보여줍니다. 그때는 `rooms.json`을 고쳐야 합니다.

## 2단계: 아이폰에서 실행

**GitHub 앱 사용:** 저장소 → Actions → "좌석 대기 예약" → **Run workflow**를 누르고 대기 시간, 열람실, 선호 좌석, 모드를 정해 실행합니다.

**중단하기:** 실행 중인 작업에서 Cancel을 누릅니다.

**단축어 앱 사용(선택):** 단축어 앱의 "URL의 콘텐츠 가져오기"로 GitHub API(`POST /repos/{owner}/{repo}/actions/workflows/seatbot.yml/dispatches`)를 호출하면 홈 화면 버튼 하나로 실행할 수 있습니다.

## 로컬 실행 및 테스트

```sh
pip install -r requirements.txt
PNU_ID=... PNU_PW=... ROOMS="3열람실-A,3열람실-D" MODE=check python -m seatbot
python -m unittest -v   # 네트워크 없이 가짜 서버로 테스트
```

## 아직 확인하지 못한 것

- **해외 IP 차단 여부:** GitHub Actions 서버는 해외에 있습니다. 학교 서버가 해외 IP를 막으면 `check` 모드에서 연결 오류가 납니다. 그런 경우 집 PC에서 실행하거나, 아이패드의 a-Shell 앱에서 실행해야 합니다. a-Shell에서는 앱을 화면에 켜둔 상태여야 계속 실행됩니다.
- **세션 만료 응답:** 로그인이 만료됐을 때 서버가 어떤 응답을 주는지는 아직 못 봤습니다. HTTP 401/403이나 로그인·인증 관련 오류 코드면 다시 로그인하도록 해 두었습니다.
- **배정 실패 응답:** 다른 사람이 먼저 잡았을 때의 오류 코드도 아직 못 봤습니다. 실패하면 다음 후보로 넘어갑니다.

## 주의사항

- **이용 규정:** 도서관 이용 규정에 매크로나 자동 예약 금지 조항이 있는지 먼저 확인하세요. 적발되면 이용 정지 등의 불이익이 있을 수 있으며, 그 책임은 사용자에게 있습니다.
- **공정한 사용:** 본인 좌석 1석만, 사람이 손으로 새로고침하는 속도(약 2초에 1번)를 넘지 않도록 만들었습니다. 최소 간격 2초는 일부러 둔 제한이니 낮추지 마세요.
- **적발 위험:** 사람은 몇 시간 동안 쉬지 않고 새로고침하지 않습니다. 2~3초 간격으로 6시간 돌리면 요청이 약 7천~1만 번 쌓여 서버 로그에서 눈에 띌 수 있습니다. 실제로 자리가 필요한 시간대에만 짧게 돌리세요.
- **GitHub 약관:** GitHub는 Actions를 저장소의 소프트웨어를 빌드·테스트·배포하는 용도로 쓰도록 정하고 있습니다. 이 봇을 오래 돌리는 것은 그 범위를 벗어날 수 있습니다.
